# TaskFlow — спецификация автоматизации

Дата: 2026-06-06. Репозиторий: `del0x3/taskflow`. Часовой пояс пользователя: UTC+3 (`Europe/Kiev`).

Личный трекер daily-задач на GitHub Issues. Задачи заводит Claude по сообщениям пользователя; пользователь смотрит и перетаскивает карточки с телефона.

## 1. Задачи

- Каждая задача — Issue. Заголовки и тело на русском.
- Метки: статус (`today`/`doing`/`blocked`/`waiting`), приоритет (`p1-critical`/`p2-high`/`p3-medium`/`p4-low`), категория (`work`/`personal`/`study`/`health`/`errand`), тип (`bug`/`feature`/`meeting`/`idea`).
- Каждый день — milestone с датой (`YYYY-MM-DD`).

### Типы по времени
- **На день** — без точного времени, без пушей. Метка `today`, висит в Todo пока не закрыта.
- **На срок** — дедлайн дата+время. В теле строка `Дедлайн: YYYY-MM-DD HH:MM` (локальное UTC+3). Заполняется поле доски `Due`. Получает пуш-напоминания.

## 2. Доска (GitHub Projects #2)

## 3. Напоминания о дедлайнах (эфемерные пуши)

Workflow `reminders.yml`, cron `*/5 * * * *` (каждые 5 мин), `GITHUB_TOKEN`.

Для каждого открытого Issue с `Дедлайн: ...` в теле:
- **За 15 мин** до дедлайна: если метки `notif-pre` нет — бот пишет коммент с маркером `<!-- tf-reminder -->` и `@del0x3` (⏰ через 15 мин), вешает `notif-pre`.
- **В момент дедлайна** (0..5 мин после): если метки `notif-due` нет — коммент `@del0x3` (⏰ дедлайн сейчас), вешает `notif-due`.

Очистка: на каждом запуске бот удаляет собственные комменты с маркером `<!-- tf-reminder -->`, созданные более 5 мин назад. Пуш на телефон уже доставлен при создании коммента; удаление чистит тред. Issue остаётся чистым.

Метки-флаги `notif-pre`/`notif-due` снимаются при закрытии не требуется (закрытая задача из выборки уходит).

## 4. Дайджесты — пирамида сворачивания

Markdown-файлы в `digests/`. Старший период вбирает младшие и удаляет их (git rm) → файлы не копятся.

| Период | Когда (UTC+3) | Файл | Удаляет |
|--------|---------------|------|---------|
| Дневной | каждый день 08:00 | `digests/daily/YYYY-MM-DD.md` | — |
| Недельный | понедельник | `digests/weekly/YYYY-Www.md` | дневные той недели |
| Месячный | 1-е число | `digests/monthly/YYYY-MM.md` | недельные того месяца |
| Квартальный | 1 янв/апр/июл/окт | `digests/quarterly/YYYY-Qn.md` | месячные того квартала |
| Годовой | 1 января | `digests/yearly/YYYY.md` | квартальные того года |

Содержимое дневного: задачи закрытые за вчера, открытые за вчера, перенесённые. Старшие — агрегат текстов младших + сводные цифры.

Плюс один постоянный Issue «📊 Текущий дайджест» (метка `digest-board`): тело перезаписывается на каждом дневном прогоне → пуш при обновлении. Не удаляется, всегда один.

## 5. Утренний прогон (`daily.yml`, cron `0 5 * * *` = 08:00 UTC+3)

Порядок:
1. Создать milestone сегодняшней даты (если нет).
2. **Роллновер**: открытые `today`-задачи прицепить к сегодняшнему milestone.
3. **Повторяющиеся**: прочитать `recurring.json`, создать задачи на сегодня.
4. **Дневной дайджест** за вчера → файл, обновить Issue «Текущий дайджест».
5. **Сворачивания**: если понедельник → недельный (+rm дневных); 1-е → месячный (+rm недельных); квартал → квартальный; 1 янв → годовой.
6. Один коммит со всеми изменениями файлов.

## 6. Повторяющиеся задачи (`recurring.json`)

```json
{ "tasks": [
  { "title": "Стендап", "labels": ["today","meeting","work","p3-medium"] }
] }
```
Пустой `tasks: []` по умолчанию — пользователь сообщает список Claude, тот наполняет.

## 7. Токены

Всё на стандартном `GITHUB_TOKEN` Actions (`issues: write`, `contents: write`). PAT не нужен, т.к. дайджесты — файлы, а напоминания — само-удаляемые **комменты** (их автор github-actions[bot] может удалять).

## Открытые риски
- Cron в Actions может задерживаться/пропускаться под нагрузкой — для личного использования допустимо.
- Точность удаления коммента «через 5 мин» зависит от 5-мин cron → реально 5–10 мин.
- Логику дайджест-сворачивания нужно валидировать на реальном проходе времени.
